# Phase 0 walkthrough — environment & bootstrap

Read this with the scripts open. Each section says **what** the piece does, **why** it is
built that way, and **what breaks** if you change it. The quiz for study gate 0 comes from
here.

---

## 1. The big picture

```
Windows (source of truth, git)  ──sync.sh (tar over ssh)──►  laptop ~/D/mlink (mirror)
                                                                │ build-kernel.sh, rbuild.sh
                                                                ▼
   ivshmem-server ── socket + eventfds + /dev/shm/mlink-shm ── QEMU "ap"   QEMU "modem"
                                                                (KVM guests, our kernel)
```

- **Why two machines?** Claude Code runs on Windows; KVM needs Linux on bare metal. The laptop
  is the "lab", the Windows repo is the "notebook".
- **Why a disposable mirror?** One direction of truth: edits happen only on Windows, the
  laptop copy is wiped each sync, so the two never drift.

---

## 2. `scripts/win/sync.sh`

- `git ls-files -co --exclude-standard` lists tracked + new (not ignored) files, so build
  artefacts and `.git` are never shipped.
- The **guard** before `find -delete`: target must not be a symlink, must `realpath` to
  exactly `$HOME/D/mlink`, and must contain `.mlink-mirror`. *What breaks without it:* a
  typo or a symlink could make the wipe delete your real files in `~/D`.
- The remote half is base64-encoded and run with `bash -c` because the laptop's login shell
  is **zsh**, which has different quoting/globbing rules (we hit that: zsh tried to glob
  `--include=Kconfig*`).
- It refuses files with CRLF line endings: a `\r` at the end of `#!/bin/bash\r` or of a
  Kbuild line produces baffling errors.

## 3. Root access: `setup-root.sh`, `mlink-bench-prep`, `msudo.sh`

- `setup-root.sh` installs packages one by one so a missing package is *skipped* instead of
  aborting everything; it validates the sudoers file with `visudo -cf` before installing it,
  because a syntax error in `/etc/sudoers.d/*` can disable sudo entirely.
- `mlink-bench-prep` is the only NOPASSWD command, and only with 4 fixed arguments. Root
  scripts that take free-form arguments are an easy privilege-escalation path.
- `msudo.sh` (decision D13): `sudo -A` asks an **askpass** program for the password; ours
  reads a 0600 file. The password never appears on a command line (`ps` would show it) or in
  output. Every call is logged to `logs/sudo.log`.

## 4. Kernel source and configs

- **Why an LTS kernel (6.18.59)?** Stable APIs for the length of the project; mainline
  changes driver APIs (e.g. `pcim_iomap_regions` → `pcim_iomap_region`) every few releases.
- **Shallow clone** (`--depth 1`): ~250 MB instead of ~5 GB of history; we never need
  history of the kernel itself.
- Config = `x86_64_defconfig` + `kvm_guest.config` + our fragments, merged with
  `scripts/kconfig/merge_config.sh`, then `make olddefconfig` fills in defaults.
- **merge_config silently drops** an option whose dependencies are not met. That is why
  `build-kernel.sh` re-reads every requested option and prints `CONFIG MISMATCH`. It caught
  one: `FRAME_POINTER` doesn't exist with x86's default **ORC** unwinder (ORC uses compact
  unwind tables generated by objtool instead of a frame-pointer register; stack traces stay
  reliable and code is faster).
- **No initramfs** → anything needed to mount root must be `=y`, not `=m`: virtio-pci,
  virtio-blk, ext4. Otherwise: `VFS: Unable to mount root fs`.
- **Two kernels:** `debug` (KASAN, lockdep, kmemleak, hung-task) finds bugs but slows code
  2–10×; `perf` (no debug options) is the only source of headline numbers.
  - KASAN: compiler-inserted checks + shadow memory (1 byte per 8 bytes) catch out-of-bounds
    and use-after-free.
  - lockdep (`PROVE_LOCKING`): records lock orderings and reports a possible deadlock the
    first time an inverse order is seen — even if it never actually deadlocked.
  - `DEBUG_ATOMIC_SLEEP`: reports sleeping in atomic context (e.g. `GFP_KERNEL` in NAPI).
- `O=$BUILD/debug`: out-of-tree build dir; one source tree serves debug/perf/kcsan builds.
- `CC="ccache gcc"`: rebuilds after a config tweak reuse unchanged object files.

## 5. ivshmem-server

- QEMU's `ivshmem-doorbell` device does not create shared memory itself; it connects to a
  **server** over a UNIX socket. The server creates the POSIX shm object
  (`/dev/shm/mlink-shm`) and passes its **file descriptor** to each QEMU with `SCM_RIGHTS`.
  It also creates one **eventfd per vector per peer** and hands every peer everyone's
  eventfds — that is the doorbell wiring.
- Writing `(peer << 16) | vector` to BAR0 `Doorbell` makes QEMU write the peer's eventfd;
  the peer's QEMU turns that into an MSI-X interrupt in the guest.
- The server isn't packaged by Debian, so we built only that target with
  `ninja ... contrib/ivshmem-server/ivshmem-server` (it's gated on `have_tools`).
- `-v` is refused in daemon mode, so `ivshmem.sh` runs it `-F -v` under `setsid` and keeps
  its own pidfile. The server deletes the shm object on exit.
- Restarting the server invalidates every eventfd → both VMs must restart too.

## 6. Rootfs: `mkrootfs.sh`

- `mmdebstrap --mode=unshare`: runs as root **inside a user namespace** (your UID mapped to
  0, plus the 100000–165535 sub-UID range from `/etc/subuid`), so files get correct root
  ownership without real root. That's why `uidmap` (newuidmap) was installed.
- Customize hooks: root `authorized_keys`, `PermitRootLogin prohibit-password` (keys only),
  `ssh-keygen -A` (host keys), locked root password, fstab with the 9p share, networkd DHCP
  matched on `Driver=virtio_net` (so it never touches `mlink0`).
- `mkfs.ext4 -d base.tar`: e2fsprogs ≥ 1.47.1 fills an image from a tarball → no loop mount,
  no root.
- **qcow2 overlays** (`-b base.img`): each VM writes only its own differences; rebuilding
  `base.img` means recreating both overlays (the script does this with `--force`).

## 7. VMs: `vm.sh`

| Flag | Why |
|---|---|
| `-enable-kvm -cpu host` | hardware virtualisation (VT-x); TCG emulation is 10–50× slower and its timing is meaningless |
| `-kernel bzImage -append ...` | boot our kernel directly, no bootloader inside the image |
| `nokaslr` | stable addresses for gdb / `lx-symbols` |
| `panic=1` + `-no-reboot` | a guest panic reboots → QEMU exits instead of looping |
| `-serial chardev:file` | console to a file on the host: a panic trace survives even when ssh is dead |
| `-nic user,hostfwd=...:2221-:22` | user-mode NAT; host port 2221/2222 → guest ssh |
| `-virtfs ... mount_tag=share` | 9p share: `mlink.ko` reaches the guests without scp |
| `-device ivshmem-doorbell,chardev=ivs,vectors=4` | our device: 4 MSI-X vectors (DATA, SPACE, STATE, TEST) |
| `-gdb tcp:127.0.0.1:1234` | kernel debugging through QEMU's gdbstub |

## 8. Out-of-tree module: `driver/`

- `Kbuild`: `obj-m := mlink.o`, `mlink-y := mlink_main.o` (one module from N files);
  `-Werror` so API drift fails the build instead of producing a subtly wrong module.
- `make -C $KDIR M=$PWD modules`: Kbuild runs in the **guest kernel's** build tree (never the
  host's — the host never loads `mlink.ko`).
- **vermagic**: a string (kernel release + SMP/preempt/modversions flags) embedded in the
  `.ko`. `insmod` refuses a module whose vermagic doesn't match the running kernel → "invalid
  module format". That's why we build against `build/debug` and boot that same `bzImage`.
- `mlink_main.c` (hello): `pci_get_device()` iterates over 1af4:1110 devices; each call
  drops the reference on the previous device and takes one on the next, so the loop leaks
  nothing when it runs to NULL. It only prints BAR sizes; it doesn't bind the device yet.

## 9. Test helpers

- `dmesg-gate.sh [marker]`: fails on `BUG:`, `WARNING:`, KASAN, lockdep, hung tasks,
  "scheduling while atomic", Oops, UBSAN, kmemleak, NETDEV WATCHDOG. With a marker it only
  looks at lines after the marker, so old noise doesn't fail new runs.
- `test.sh`: build → stage → in each guest: write marker to `/dev/kmsg`, insmod, rmmod,
  dmesg gate → PASS/FAIL. Grows in P3.9 into the full smoke test.
